# 闲鱼游戏本 · 低价筛选

按你的要求重做的版本：**只做游戏本、只认 N 卡、拿你自己的《笔电行情》表当参考价，低于表价 100 以上才看**。

它只抓搜索列表；对初筛候选（每轮最多 5 条）再打开详情页读描述做细筛，不逐条爬 200+ 商品、不聊卖家、不下单——只负责“找出来 + 排好序 + 给链接”，剩下的你人工判断。

> **v2.3.1 修复**：企业微信/Bark 改为按响应体状态码判定成功，HTTP 200 但 `errcode`/`code` 失败不再记为已推送，条目会留在队列下轮重试；`scan --demo` 不再发送真实推送；Bark 标题显示本次实际发送条数。
>
> **v2.3.0 新增**：熔断拆成搜索风控 / 详情风控 / 软失败三套计数，部分成功不再清零；冷却 24 小时起步、重复触发翻倍，重新登录只保留最短冷静期；登录只校验 cookie、不再自动试搜；手动与定时扫描互斥；日志按天切分并记录请求数、风控次数和耗时。
>
> **本版变更**：已删除卖家主页审核模块（原“大疆/无人机 → 骗子排除、苹果设备计数、主页商家确认”）。
> 现在只靠标题/昵称做商家硬排除，**不再自动识别骗子**，低价异常请自行核实。

## 一分钟看懂它怎么筛

```
搜索（游戏本 3060 / 4060 / 2060 …，先筛「个人闲置」+「新发布·最新」）
  → ① 硬排除：商家、空机、缺内存/硬盘、内存 <8G、硬盘 <120G、无法开机 → 直接丢
  → ② 品类闸门：苹果、华为、轻薄本、工作站、台式显卡、无 N 卡 全部丢掉
  → ③ 行情表比价：按「型号 + 显卡」匹配你表格里的收机价
  → ④ 价差底线：比表价低不到 100 的直接不看
  → ⑤ 初筛候选抓详情页描述，再按硬规则复筛（默认最多 5 条，抓过的缓存复用）
  → ⑥ 打分排序：价差深度 + 显卡档位 + 品牌权重 + 新鲜度 - 想要人数
  → ⑦ 输出 links：reports/latest.html（可点）+ CSV + Markdown
```

## 筛选规则（完全按你的要求）

### 1. 只留游戏本，必须有 N 卡

- **排除**：苹果（MacBook）、华为（MateBook）
- **排除**：轻薄本、超极本、商务本、办公本、学生本、全能本、创作本、设计本、二合一、平板
- **硬排除**（标题写了“游戏本”也不放行）：工作站、移动工作站、Quadro / RTX A 系列专业卡、台式机/台式、迷你主机、一体机、求购、租赁、出租、拆机；“无拆机 / 无拆修 / 不是工作站”这类否定句不算
- **配件排除**：电脑包、内胆包、鼠标垫、散热底座、硬盘盒、键盘膜、保护壳、屏幕总成、贴纸、配件机等直接丢；鼠标、键盘、电源适配器、充电器、显示器、支架等只在标题看不出是整机时丢
- **不误杀**：「送鼠标键盘」「带原装电源适配器」「原装配件齐全」「比台式机便携」「可外接显示器」「三风扇散热」都按整机处理
- **必须有英伟达显卡**：标题里能识别出 GTX/RTX + 型号才进入下一轮；A 卡直接丢

标题里没有“笔记本”三个字时，还会用常见游戏本系列名兜底（拯救者 / 天选 / 蛟龙 / 战神 / 暗影精灵 / 掠夺者 / 雷神 / 机械师 …）。**认不出的就当台式显卡处理，不冒险。**

### 1.1 商家 / 开机故障硬排除（直接丢，不打分）

标题或候选详情描述命中以下任一条，就不进评分、不进报表、不进推送：

- **空机 / 缺件**：空机；无内存、没内存、没有内存、不含内存、缺内存；无硬盘、没硬盘、没有硬盘、不含硬盘、缺硬盘；无固态、没有固态、不含固态；内存硬盘都没有 / 全无 / 均无
- **内存 < 8G**：明确写 `4G 内存` 这类才丢；`8G` 保留，没写容量不丢
- **硬盘 < 120G**：明确写 `64G 固态` 这类才丢；`120G`、`128G` 都保留，没写容量不丢
- **开机故障**：无法开机、开不了机、不能开机、不开机、点不亮

这些写法不会误杀：

- 否定句：`不是空机`、`无拆修`
- 扩展位：`无硬盘位`、`无内存插槽`、`无硬盘接口`
- 能力值：`最大支持 32G`、`可升级到 16G`；`已升级到 16G` / `已加装 1T` 按实际容量算
- `黑屏` / `花屏` 不硬排除，仍按故障描述扣分，并在审核页打上「异常低价」标签待核实

详情页只给**初筛候选**抓，默认每轮最多 `scan.detail_limit: 5` 条，不会逐条打开 200+ 商品。只有整轮搜索没有任何错误时才抓详情；抓过的描述存入数据库复用，已联系/已成交/已忽略的商品不再重复打开。旧待审核商品只有在下一次扫描仍出现、且命中硬规则时才会自动移入「已忽略」。

### 2. 品牌权重

| 品牌 | 处理 |
|---|---|
| 苹果、华为 | **直接排除** |
| 华硕（ROG/天选/飞行堡垒）、机械革命、联想（拯救者）、微星、神舟、七彩虹 | **+6 ~ +8 分** |
| 惠普、戴尔、宏碁、雷神、机械师、未来人类、技嘉、火影 | 0 分 |
| 其他 | 0 分 |

### 3. 行情表就是参考价

- 读你表格的 `名称 / CPU / GPU / 内存 / 硬盘 / 价格` 列，按 **显卡 + 型号名** 匹配；
- 匹配不到型号就用**同显卡档位的中位数**（比如 3060 的 10 条收机价中位数 ¥2,899）；
- 表里没有的显卡用相邻档位估算（3070 ≈ 3060 × 1.25，4070 ≈ 4060 × 1.3 …）；
- 标题写明 `4G/8G/32G 内存`、`128G/1T 硬盘` 时，会按配置对表价加减（4G −300、8G −150、32G +200…）。

**价差底线：低于表价 100 元才进打分。** 这条是硬门槛，不是扣分。

### 4. 显卡档位分

| 显卡 | 分数 | 显卡 | 分数 |
|---|---|---|---|
| 2060 | **+12** | 4060 / 4060Ti | **+15** |
| 3050 / 3050Ti | **+10** | 4050 | **+12** |
| 3060 / 3060Ti | **+14** | 3070 / 3080 | +7 |
| 2070 / 2080 | +6 | 4070 / 4080 / 4090 | +7 |
| 1660 / 1660Ti | +4 | 50 系（5050~5090） | **−10** |
| 1060 / 1070 / 1080 | 0 / +3 | 1050 / 1050Ti | **−25** |
| 1650 / 1650Ti | −6 | | |

Ti / Super 变体与基础型号同分；未收录的变体先回退到基础型号分数，再按系列兜底。

### 5. 新鲜度 vs 想要人数

- 2 小时内上架 **+10**，6 小时内 **+7**，24 小时内 **+4**，3 天内 +1；
- 想要 ≥100 人 **−8**，≥50 人 **−4**（抢的人多，轮不到你压价）。

### 6. 商家（标题/昵称，直接排除）

- 标题命中 `signals.merchant`：`店铺 / 实体店 / 批发 / 回收 / 工作室 / 数码城 / 专营店 / 大量到货` → **直接丢**
- 卖家昵称命中 `filters.seller_exclude`：`店铺 / 实体店 / 批发 / 回收 / 工作室 / 数码城 / 专营店 / 数码` → **直接丢**
- 商家商品不进入打分、不进报表；旧待审核商品再现时自动移入「已忽略」，显示命中原因

> 注意：本版**不再打开卖家主页**做审核。主页在售数量、已售数量、是否卖大疆/无人机、是否卖苹果设备，均不再自动检查。

## 打分公式（透明版）

```
分数 = 20（基础）
     + 价差分（0~40，按 低/表价 的比例给，低 100 是 0 分起点）
     + 显卡分（−25 ~ +15）
     + 品牌分（0 ~ +8）
     + 新鲜度（0 ~ +10）
     + 成色（全新/在保 +，磕碰/进水 −）
     − 想要人数（0 ~ −8）
```

- `≥80` 强烈推荐 · `≥68` 推荐 · `≥55` 可看 · 低于 55 不进报表
- 定金 / 进水 / 账号锁 / 坏机等，打分压到 35 以下，并在审核页打上「异常低价」标签

| 文件 | 用途 |
|---|---|
| `reports\latest.html` | 主报表：显卡/品牌/参考型号/折价/分数/理由，点标题跳闲鱼 |

人工审核页（记录你自己“采纳 / 已联系 / 已成交 / 忽略”的状态，不是卖家审核）：

```bat
review.bat            :: http://127.0.0.1:8765
```

## 推送（可选）

在 `config.yaml` 填企业微信群机器人或 Bark 地址即可；不填就完全不发。

```yaml
notify:
  wecom_webhook: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=..."
  bark_url: "https://api.day.app/你的key"
  min_score: 75
```

- 只推「不异常」且分数 ≥ `notify.min_score` 的商品；
- 每条商品只成功推一次：企业微信一轮最多 8 条、Bark 最多 5 条，超出部分下一轮补发；
- 成功与否以响应体为准：企业微信要求 `errcode=0`，Bark 要求 `code=200`；HTTP 200 但状态码失败不会写入已推送标记；
- 发送失败或响应异常不会写入已推送标记，下次扫描自动重试；
- 手动扫描和可选定时任务都会推送；`scan --demo` 只演示，不发送真实推送。

## 运行方式（手动为主）

日常需要看货时手动跑：

```bat
scan.bat
```

**不建议长期挂定时任务**：闲鱼风控看的是请求频率，自动轮询只会让账号更早被要求验证。确实需要兜底时再注册，脚本默认 60 分钟：

```powershell
powershell -ExecutionPolicy Bypass -File .\register_task.ps1            # 每 60 分钟（可选）
powershell -ExecutionPolicy Bypass -File .\register_task.ps1 -Minutes 90
powershell -ExecutionPolicy Bypass -File .\register_task.ps1 -Unregister
```

日志按天写在 `logs\scan-YYYY-MM-DD.log`，每轮记录状态、搜索/详情请求数、搜索风控/详情风控/软失败次数和耗时。手动扫描与定时任务共用一把跨进程锁，后启动的一轮会直接跳过，不会重叠请求。

间隔低于 30 分钟会明显增加风控概率。

### 遇到风控

- 任意一轮搜索**首次**遇到风控，本轮立即停止，不再跑剩余关键词，也不会自动切有头模式重试；
- 按终端提示用 `scan.bat --headed` 手动过验证、检查登录，确认页面正常后再重新运行；
- 不要连续重试。搜索风控、详情风控、软失败（0 条结果、超时、未知接口错误）**分别计数**，各自连续 `failure_threshold` / `detail_failure_threshold` / `soft_failure_threshold` 轮（默认都是 3）后进入冷却；
- 冷却从 24 小时起步，重复触发逐次翻倍，风控上限 7 天；软失败从 1 小时起步，上限 24 小时；
- **部分成功不清零**：只有一整轮所有关键词都跑完、没有任何错误、且至少拿到一条结果，才把三套计数和冷却等级全部清零；
- 熔断后重新 `login.bat` 扫码**不会立即解除**：剩余冷却最多缩短到“登录后 `login_quiet_minutes`（默认 60 分钟）”，计数不会清零；`scan.bat --force` 可强跑一次，但不会绕过计数。

## 能力范围（确认，不是扩展）

你的主链条是：登录搜索 → 了解行情 → 筛选 → 聊卖家 → 下单 → 整备上架 → 买家沟通 → 提交发货。

**这个项目只覆盖其中两段：**

| 环节 | 状态 | 说明 |
|---|---|---|
| 1. 登录态搜索 | ✅ 已实现 | Chrome 扫码，复用登录态，自动翻页 |
| 2. 自动了解行情 | ⚠️ 静态 | 用你的 Excel 收机价，**不是**动态抓成交价；表要你自己更新 |
| 3. 按行情筛选 | ✅ 已实现 | 品类/显卡/品牌/价差/打分排序 |
| 4. 与卖家聊天 | ❌ 不做 | 闲鱼没有开放接口，模拟 IM 风险高、易封号 |
| 5. 下单 | ❌ 不做 | 涉及支付与账号安全 |
| 6. 整备后上架 | ❌ 不做 | 线下流程 |
| 7. 与买家沟通 | ❌ 不做 | 同上 |
| 8. 提交发货 | ❌ 不做 | 同上 |

**它就是一个“选品雷达”，不是全自动店铺。** 第 4~8 步目前没有可靠且合规的自动化方式，建议保持人工。

其它已知边界：

- 型号匹配靠标题文字，卖家写错/不写型号时会退到“同显卡中位数”；

- 行情表里没有的显卡用相邻档位估算，价格会粗一些。

## 配置怎么改

全在 `config.yaml`：

```yaml
scan:
  min_gap: 100      # 低于表价多少才看
  min_score: 55     # 进报表的最低分
  detail_limit: 5   # 每轮最多抓 N 条详情；抓过的会缓存；0 = 关闭
  failure_threshold: 3           # 连续 N 轮搜索风控后熔断；0 = 关闭
  detail_failure_threshold: 3    # 连续 N 轮详情风控后熔断；0 = 关闭
  soft_failure_threshold: 3      # 连续 N 轮 0 结果/超时/未知错误后熔断；0 = 关闭
  cooldown_minutes: 1440         # 风控冷却起步 24 小时，重复触发翻倍
  cooldown_max_minutes: 10080    # 风控冷却上限 7 天
  soft_cooldown_minutes: 60      # 软失败冷却起步 1 小时
  soft_cooldown_max_minutes: 1440 # 软失败冷却上限 24 小时
  login_quiet_minutes: 60        # 熔断后重新登录的最短冷静期

notify:
  wecom_webhook: "" # 企业微信群机器人地址
  bark_url: ""      # Bark 推送地址
  min_score: 75     # 推送分数线

watches:            # 搜索词，按显卡档位搜
  - name: 游戏本 3060
    keyword: 游戏本 3060
    pages: 2
```

改完下一次运行立即生效。

## 常见问题

**行情表导不进去**
确认表头有 `名称` 和 `价格` 两列，且每个 sheet 是按显卡分的。导入失败会提示具体原因。

**一个都筛不出来**
先看终端打印的「排除原因」：如果是“比行情表还高”，说明现在挂牌价普遍高于你的收机价，这很正常；如果是“看不出是笔记本”，说明标题太简略，可以往 `watches` 里加具体型号词。

**提示 RGV587 / 抓不到**
风控。脚本会立即停止本轮，不再继续请求；先用 `scan.bat --headed` 手动过验证并确认登录态，等一段时间再跑，不要连续重试。搜索风控、详情风控和软失败分别计数，连续 3 轮触发后自动冷却（风控 24 小时起步、逐次翻倍；软失败 1 小时起）。一整轮完全干净才会清零；重新登录不会立即解除，剩余冷却最多缩短到登录后 60 分钟；`scan.bat --force` 可强跑一次。

**页面显示“非法访问”**
脚本已自动伪装 UA；仍出现就 `--headed`，或在 `config.yaml` 填 `browser.user_agent`。

## 技术说明

- Python 3.12 + Playwright 1.64，复用本机 Chrome；
- 抓的是 `mtop.taobao.idlemtopsearch.pc.search`，登录态由真实浏览器发出，脚本只旁路读 JSON；
- 无头模式会自动替换 `HeadlessChrome` UA，否则闲鱼直接返回“非法访问”；
- 数据落在 `data\xianyu.db`（SQLite），审核状态、推送记录和详情描述缓存都在同一个库里；
- 风控熔断状态在 `data\risk_guard.json`，删除该文件可重置（冷却期内不建议手动删）；
- 扫描锁是 `data\scan.lock` 上的系统文件锁，进程退出或崩溃后自动释放；
- 每日日志在 `logs\scan-YYYY-MM-DD.log`。
